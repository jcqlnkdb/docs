title: 'Managing tasks'
description: 'Common workflows for creating, updating, and removing tasks'

This guide walks through the most common task management workflows: progressing a task through its lifecycle, editing its content, and removing it when no longer needed. Each workflow uses the same `task_id` you receive when creating the task.

## From creation to completion

Tasks move through three states during their lifecycle: `pending`, `in_progress`, and `done`. The following workflow shows how to progress a single task from start to finish.

### 1. Create the task

```bash
curl --request POST \
  --url https://test-writechoice.onrender.com/tasks \
  --header 'Authorization: Bearer tf-live-4a8f2c1e9b3d7e6a' \
  --header 'Content-Type: application/json' \
  --data '{
    "project_id": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
    "title": "Write introduction page"
  }'
```

The new task is returned with `status: "pending"`:

```json
{
  "task_id": "f9e8d7c6-b5a4-3210-fedc-ba9876543210",
  "project_id": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
  "title": "Write introduction page",
  "description": null,
  "status": "pending",
  "created_at": "2026-05-17T10:35:00.000Z",
  "updated_at": "2026-05-17T10:35:00.000Z"
}
```

Save the `task_id` — you will need it for all subsequent operations.

### 2. Move the task to in_progress

When work begins, update the status with a `PATCH` request:

```bash
curl --request PATCH \
  --url https://test-writechoice.onrender.com/tasks/f9e8d7c6-b5a4-3210-fedc-ba9876543210 \
  --header 'Authorization: Bearer tf-live-4a8f2c1e9b3d7e6a' \
  --header 'Content-Type: application/json' \
  --data '{
    "status": "in_progress"
  }'
```

The response returns the full task with the updated status and a refreshed `updated_at` timestamp.

### 3. Move the task to done

When the work is complete:

```bash
curl --request PATCH \
  --url https://test-writechoice.onrender.com/tasks/f9e8d7c6-b5a4-3210-fedc-ba9876543210 \
  --header 'Authorization: Bearer tf-live-4a8f2c1e9b3d7e6a' \
  --header 'Content-Type: application/json' \
  --data '{
    "status": "done"
  }'
```

The task remains in the system as a record of completed work.

## Editing task content

Use the same `PATCH /tasks/{task_id}` endpoint to update a task's `title` or `description`. PATCH is partial — include only the fields you want to change.

```bash
curl --request PATCH \
  --url https://test-writechoice.onrender.com/tasks/f9e8d7c6-b5a4-3210-fedc-ba9876543210 \
  --header 'Authorization: Bearer tf-live-4a8f2c1e9b3d7e6a' \
  --header 'Content-Type: application/json' \
  --data '{
    "title": "Write the introduction and overview",
    "description": "Cover the API purpose, capabilities, and limitations."
  }'
```

The `updated_at` timestamp refreshes after any successful PATCH, regardless of which fields changed.

## Removing tasks

Two operations remove a task from active workflows, with very different effects:

- **Marking as `done`** keeps the task in the system. It remains visible in task listings and preserves the history of completed work.
- **Deleting the task** removes it permanently. The task no longer appears in any listing, and the data cannot be recovered.

To delete a task, send a `DELETE` request:

```bash
curl --request DELETE \
  --url https://test-writechoice.onrender.com/tasks/f9e8d7c6-b5a4-3210-fedc-ba9876543210 \
  --header 'Authorization: Bearer tf-live-4a8f2c1e9b3d7e6a'
```

<Warning>

Deletion is permanent. TaskFlow has no undo or trash mechanism. Use `DELETE` only when you want the task to disappear entirely.

</Warning>

## Best practices

- **Store every `task_id` you create.** TaskFlow does not allow retrieving a single task by ID; the only way to access a task later is through the project's task list.
- **Treat `404 Not Found` as a predictable response.** A task may have been deleted between requests. Handle this case gracefully in your integration.
- **Account for cold starts in your UI.** The TaskFlow test server can take up to 60 seconds to respond on the first request after idle. Consider showing a loading state to users.
