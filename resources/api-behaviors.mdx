This page gathers operational behaviors that affect how you integrate with the TaskFlow API. These details are not formally part of the endpoint specifications but are important to know for production use.

## Cold start

The TaskFlow test server enters an idle state when not in use. The first request after idle may take up to 60 seconds to respond. Subsequent requests respond immediately.

<Tip>

Consider sending a warm-up request before latency-sensitive operations, especially when running automated tests or demos.

</Tip>

## Rate limits

TaskFlow does not document public rate limits. As a general best practice, implement retry logic with exponential backoff in production code to handle transient failures and any undocumented limits gracefully.

## Identifier format

Both `project_id` and `task_id` are UUID version 4 strings, generated by the API at creation time. They are:

- **Immutable** — they never change after a resource is created
- **Unique** — no collisions across resources of the same type
- **Required for subsequent operations** — store them in your own system as you receive them

## Timestamp format

All `created_at` and `updated_at` fields use ISO 8601 format in UTC, with millisecond precision and a `Z` suffix indicating the UTC zone.

Example: `"2026-05-17T15:55:43.764Z"`

When parsing timestamps in your code, treat the `Z` as equivalent to `+00:00`.

## Field defaults

- Optional fields omitted from a request body return as `null` in the response. For example, omitting `description` when creating a project returns `"description": null`.
- New tasks always begin with `status: "pending"`. There is no way to create a task in another state directly — use a subsequent PATCH to change it.

## Update timestamps

The `updated_at` field refreshes on any successful PATCH. On newly created tasks, `updated_at` is initially equal to `created_at`.

## Empty list behavior

When listing tasks in a project that exists but has no tasks, the API returns `200 OK` with `tasks: []` and `total: 0`. This is a valid response, not an error condition.
